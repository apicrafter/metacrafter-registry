The issue asks to add the organization identifiers listed by
[ORG-ID.guide](https://org-id.guide/results?structure=all&coverage=all&sector=all).

Sources reviewed:

- The full register as published at <https://org-id.guide/download.json>
  (downloaded 2026-11-04; 569 lists). It is generated from
  [org-id/register](https://github.com/org-id/register), whose head was commit
  `1830c63dd74935b07c66f9c0b65522c3fe992379` (2026-10-22). The register is

- The ORG-ID.guide [About page](https://org-id.guide/about), which defines the

  (`GB-COH-09506232`) or in two fields (`{"scheme": "GB-COH", "id": "09506232"}`).
- The identifier guidance of the
  [Open Contracting Data Standard](https://standard.open-contracting.org/latest/en/schema/identifiers/)
  and of [IATI](https://iatistandard.org/en/guidance/preparing-organisation/organisation-account/how-to-create-your-iati-organisation-identifier/),
  which both take their list codes from ORG-ID.guide.

## What ORG-ID.guide is

ORG-ID.guide is a register of **lists of organization identifiers**: company
registers, charity registers, tax authorities, government agency lists and a
few third-party databases (LEI, D-U-N-S, ROR, Wikidata). Each list has a code
such as `GB-COH` (Companies House). An organization identifier is the code of
the list, a hyphen and the identifier from that list: `GB-COH-09506232`. IATI,
360Giving and Open Contracting use these codes.

A list is not a value type by itself; the identifiers in the list are. So the
registry gets:

- two **generic records** for the ORG-ID.guide form itself;
- a **crosswalk key** `mappings.orgid` that links each list code to the record
  of the identifier that the list uses;
- **new draft records** for list identifiers that the registry did not have.

The 569 lists split like this:

|---|---:|---|

| Mapped to a new record | 182 | 175 new draft records |

| Generated Chart of Accounts list (`*-COA`) | 250 | not added |
| **Total** | **569** | |

## Summary

- **Done in this change:**
  - New draft record `org_id`: an organization identifier in the ORG-ID.guide
    form (`GB-COH-09506232`). Its regexp is the list code pattern, a hyphen and
    an identifier without spaces.
  - New draft record `org_id_scheme`: an ORG-ID.guide list code (`GB-COH`),
    the value of `identifier.scheme` in Open Contracting data. Its regexp
    matches all 569 codes of the register (checked).
  - New crosswalk key `mappings.orgid`. The schema accepts list codes only
    (`GB-COH`, `CA_ON-ONT`, `BE-BCE_KBO`) and rejects a whole identifier or a
    lowercase code. Each code maps to at most one record (a test checks this).
  - `crosswalk("orgid", ...)` accepts a list code in any case, its
    `https://org-id.guide/list/<code>` URL or a whole ORG-ID.guide identifier:
    `crosswalk("orgid", "GB-COH-09506232")` returns `companyhouseid`.
  - Record pages show the ORG-ID.guide codes as links to the list pages.
  - 69 list codes are mapped to 61 existing records. Six of them are
    deprecated codes that ORG-ID.guide replaced with a list that uses the same
    identifier (for example `SE-BLV` and `SE-KK`, now `SE-ON`, on
    `seorgnumber`), so that old IATI data still resolves. The deprecated
    `SK-ZRSR` is mapped the same way to the new record `sk_ico`.
  - 175 new draft records for the identifiers of 182 lists (four records
    cover more than one list, see below). New countries: 57. New languages: 22.
- **Not done, on purpose:**
  - No regexps for the new records. ORG-ID.guide gives example identifiers
    and sometimes a short note on the format, not a specification. Regexps
    need the issuing authority's documentation; see [Follow-ups](#follow-ups).
  - No records for the 250 Chart of Accounts lists. They are generated by Gov
    Org ID Finder for every country, and most hold no codes at all.
  - No records for current lists that give no example identifier (among them
    14 UAE chambers of commerce and free zones and 12 Canadian provincial
    corporate registries): the registry would know nothing about the value.
  - No changes to the regexps of existing records. Some of them reject the
    ORG-ID.guide examples; they are listed in [Follow-ups](#follow-ups).

## How the new records were made

- **One record per identifier, not per list.** Lists that use the same
  identifier share one record:
  - `ge_identification_code`: `GE-NAPR` and `GE-RS`. NAPR assigns the
    identification code, and the Revenue Service uses the same code.
  - `sk_ico`: `SK-ICO`, `SK-ORSR` and the deprecated `SK-ZRSR`. All three use
    the IČO; their example identifiers are IČO numbers.
  - `kg_inn`: `KG-TIN` and `KG-INN`, which both hold the ИНН.
  - `gb_local_authority_code`: the four local authority registers of the UK
    Government Digital Service (`GB-LAE`, `GB-LANI`, `GB-LAS`, `GB-PLA`). All
    use three-letter codes based on ISO 3166-2:GB.
- **Ids** follow the registry convention `<cc>_<name>`, with the name of the
  identifier where it has a well-known one (`ua_edrpou`, `kz_bin`, `in_cin`,
  `pl_krs`) and otherwise the register (`gh_company_number`,
  `ke_ngo_number`). International identifiers have no country prefix
  (`eori`, `permid`, `ebid`, `oecd_dac_code`).
- **Descriptions** are written for the registry from the list's name,
  coverage and organization types. Other facts come from the list's
  ORG-ID.guide description or guidance (for example "a 15-digit code" for
  `CO-CUIN`), from its example identifiers (the digit counts of `ua_edrpou`
  or `pl_krs`), or are widely documented (the UEI replaced the DUNS number in
  US federal awards in 2022). Each description ends with the ORG-ID.guide code
  and an example of the identifier in the ORG-ID.guide form. No text is copied
  from ORG-ID.guide.
- **Examples** are the example identifiers of the list, split into single
  values. Removed: placeholders (`U12345678`, `01234567`, `CC12345`,
  `XXX-XXX-XXX-XX`), junk (`TRUE`, "Unable to find"), values that contradict
  the list's own guidance (a 9-digit VÖEN where the guidance says 10 digits,
  a 13-digit Kyrgyz INN next to 14-digit ones) and a KRA PIN that starts with
  `A`, the prefix of individuals. The identifiers are those of organizations,
  not people.
- **`is_pii`** is `true` for tax identification numbers (TIN, NIF, NIT, PIN,
  RTN, NTN, PAN, PIB, VÖEN, ...), because these schemes also number
  individuals, and `false` for registers of companies, charities and public
  bodies.
- **`langs`** are the official languages of the country.
- **Links:** the list page on ORG-ID.guide (`other`) and the register's own
  site (`doc`) when it answered HTTP 200 on 2026-11-04. ORG-ID.guide also
  gives Wikipedia links for some lists, but they describe the issuing agency,
  not the identifier, so they are not used.
- **Status:** all new records are `draft`.

### Chart of Accounts lists

The 250 lists with codes ending in `-COA` (for example `AD-COA`) are generated
by [Gov Org ID Finder](https://gov-id-finder.codeforiati.org/about) for the
government budget (Chart of Accounts) of each country. Each country's budget
uses its own codes, most of these lists hold no codes yet, and none gives a
format. They are not imported.

## Follow-ups

- **Regexps for the new records.** ORG-ID.guide states some formats (the
  15-digit `co_cuin`, the 7-digit `gb_scottish_seed_code` and
  `gb_welsh_school_number`, the 7-digit `mk_embs`, the 10-digit `az_voen`).
  Others are well known but need a check against the issuing authority:
  `ua_edrpou`, `kz_bin`, `pl_krs`, `cz_ico`, `sk_ico`, `lt_company_code`,
  `lv_registration_number`, `in_cin`, `nz_nzbn`, `us_uei`, `rs_maticni_broj`,
  `rs_pib` and `za_company_number`. Several of them also have check digits.
- **Regexps of existing records that reject ORG-ID.guide examples:**

  | Record | Regexp | ORG-ID.guide example | Problem |
  |---|---|---|---|
  | `seorgnumber` | `^[0-9]{9}$` | `556091-2148` | the organisationsnummer has 10 digits |
  | `taxid` | `^[0-9]{9,15}$` | `G1610000713522976L` | the Unified Social Credit Identifier has 18 characters |
  | `acra` | `^[0-9]{9}[A-Z]$` | `52813269E` | UENs of businesses have 8 digits and a letter |
  | `cnpj` | `^[0-9]{2}\.[0-9]{3}\.[0-9]{3}/[0-9]{4}-[0-9]{2}$` | `02326629-0001-51` | only the punctuated form matches |
  | `idnpwp` | `^\d{2}\.\d{3}\.\d{3}\.\d-\d{3}\.\d{3}$` | `010117771077000` | only the punctuated form matches |
  | `auabn` | `\d{2}\s\d{3}\s\d{3}\s\d{3}` | `52093617380` | only the spaced form matches |
  | `usein` | `[0-9]{9}` | `03-0413726` | the usual form has a hyphen |
  | `cacorp` | `^[0-9]{7,9}$` | `784899-4` | the check digit can follow a hyphen |
  | `si_tin` | `^[1-9]\d{7}$` | `SI99190591` | the VAT form adds `SI` |
  | `handelsregisternr` | `^[A-Z][0-9]{1,6}$` | `RA000220-VR8726` | ORG-ID.guide adds the register court; the register number itself (`HRB 758147`) does not match either |

- **Near-duplicate records** met during the mapping. The ORG-ID.guide code
  went to the first record of each pair: `auabn` / `abn`, `sirencode` /
  `siren`, `nutsregion` / `eunuts`, `ukurn` / `ukestablishmentnumber`, `cif` /
  `nif` (`nif` also covers individuals). Merging the pairs with aliases is a
  separate change.
- **Lists without examples** (UAE, Canadian provinces, Mozambique, ...) can get
  records when their identifier is documented.
- **Data license.** The ORG-ID.guide register is under the ODbL. This change
  takes facts from it (list codes, names, example identifiers), not its text.
  Attribution belongs with the data license work of task 9.1.
