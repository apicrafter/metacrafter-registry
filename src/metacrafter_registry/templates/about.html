About the registry

The Metacrafter Registry is a reference catalog of semantic data types: what a value means, not only how it is stored. Examples are an email address, a Russian INN, an IBAN or an ISO country code.

Each datatype has an ID, a name and a description. It may also have:

  • categories (contexts of use)
  • countries and languages
  • a flag that marks personal data (PII)
  • a regular expression
  • examples
  • translations
  • links to Wikipedia, Wikidata, Schema.org and standards

Each record has a status. Stable records have been reviewed. Draft records, for example those generated from detection rule keys, have not been reviewed yet and may be incomplete. Each record also has a quality score from 0 to 100 that lists what is missing.

A pattern is one specific representation of a datatype, for example the UK passport number format. A tool record lists the registry types that a piece of software supports.

Metacrafter labels the fields of tables and data files with these IDs. For every detected type, it links to {{ site_url }}/datatype/<id>. Its detection rules live in metacrafter-rules, and each rule key is a registry ID.

How it is built

The source of truth is one YAML file per record in the GitHub repository. Every change is validated in CI. Each merge to main rebuilds this static site and the JSON files, and deploys them to GitHub Pages. This build:

API

All endpoints are static files: plain GET requests, with no key, no rate limit and no query parameters. They are described in OpenAPI 3.1.

PathContent
/api/v1/index.jsonManifest: data version, git SHA, counts, size and SHA-256 of every bulk file, datatype URL template
/api/v1/datatypes/<id>.jsonOne datatype or pattern, normalized: references are ID strings
/api/v1/datatypes.jsonAll datatypes and patterns (array); also .jsonl and .csv
/api/v1/tools/<id>.jsonOne tool; all tools in /api/v1/tools.json
/api/v1/categories.jsonCategories with counts; also countries.json, languages.json
/api/v1/aliases.jsonRetired IDs and the record each one now resolves to
/schema/*.schema.jsonJSON Schemas of the source YAML records (datatype, pattern, tool)
/registry.jsonLegacy: all records keyed by ID, in the shape used by metacrafter's RegistryClient
/datatype/<id>.jsonLegacy: one record, same shape as in registry.json

The legacy files keep the release 1.02 shape: fields are added, never removed or retyped. New integrations should use /api/v1/.

Contributing

Every record page has an “edit on GitHub” link. To propose a new datatype, open a pull request or an issue. The rules are in CONTRIBUTING.md.
