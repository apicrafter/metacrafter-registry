# Ревизия категории «Publishing and print» (ноябрь 2026)

Цель: проверить записи категории `publishing`, исправить неточные и
устаревшие поля, добавить отсутствующие типы, которые встречаются в
библиографических, библиотечных, издательских и наукометрических данных.

## Источники проверки

- Свойства Wikidata: регулярное выражение формата (P1793), примеры
  (P1855) и выборки до 3000 значений каждого свойства через Wikidata Query
  Service. Подписи примеров взяты из элементов Wikidata.
- python-stdnum 2.2: контрольные символы ISSN, ISMN, ISNI и ORCID на тех
  же выборках (15 000 значений, расхождений с новыми алгоритмами нет),
  длина ISIL.
- Wikipedia: CODEN, Bibcode, ISIL, ISO 216, Dewey Decimal Classification,
  BISAC Subject Headings; ru.wikipedia — ГРНТИ, ББК.
- Документация: ORCID (блоки номеров), RFC 8458 (URN:NBN), страница ГРНТИ
  ГПНТБ России и рубрики grnti.ru, справка ADS о bibcode.
- Правила metacrafter-rules на закреплённом коммите `19823306`, проверены
  pyparsing 3.

## Было

21 запись с категорией `publishing` (5 `stable`), средняя оценка 88,3.
Ещё 11 библиотечных и библиографических идентификаторов (`doi`, `isni`,
`ocn`, `lccn`, `viafid`, `gnd_id`, `openlibid`, `udkindex` и др.) не
входили в категорию. Проблемы:

| Запись | Проблема |
|---|---|
| `issn` | Описание скопировано из Wikipedia; нет проверки контрольной цифры; regexp не принимает форму без дефиса с X (`0960894X`); примеры без подписей. |
| `isni` | Описание скопировано из Wikipedia; нет проверки MOD 11-2; пример «Norway» не найден в Wikidata. |
| `orcid` | Описание скопировано из Wikipedia; regexp не принимает iD из блока `0009-`, который ORCID выдаёт новым пользователям; нет проверки MOD 11-2. |
| `ocn` | Описание скопировано из Wikipedia вместе со сноской `[42]`. |
| `doi` | Описание и русский перевод скопированы из Wikipedia; `parent: url`, хотя DOI — не URL, а handle с префиксом 10. |
| `udkindex` | Описание и перевод скопированы из Wikipedia; категория `common`; `classification: identifier` у классификации; regexp принимал только основной номер и знаки `: + /`, 274 из 467 значений Wikidata (не принимал `94(47)`, `821.163.42-13`, `323.12(=161.1)`). |
| `coden` | Regexp требовал пятую букву A–F; у журналов, начатых после 2000-х, бывают другие (`NUTRHU` — Nutrients, `NANOKO` — Nanomaterials); отрицательный пример `NATUGS` был неверным. |
| `bibcode` | Regexp не принимал цифры в коде издания (`HSFR1`), пятую цифру номера страницы в квалификаторе (arXiv), дефис в странице (`2008AgrJ..100.-166S`) и точку вместо инициала автора. |
| `isil` | Длина ограничена 15 символами (по python-stdnum), стандарт допускает 16; примеры подписаны «Real-world value published online». |
| `ismn` | Синтетические примеры; нет проверки контрольной цифры. |
| Остальные | Нет отрицательных примеров и русских переводов. |

## Изменения существующих записей

- **Новые алгоритмы контрольных цифр** в `checksums.py` и `identify-core.js`
  (с тестами и проверкой совпадения Python и JavaScript):
  - `issn` — ISO 3297, веса 8…1, модуль 11, X = 10;
  - `ismn` — ISO 10957, GS1 mod 10 13-значной формы, `M` = `979-0`;
  - `iso7064_mod11_2` — ISNI и ORCID.
- `issn`, `issn_l`: описание своими словами, `checksum: issn`, regexp
  `^\d{4}-?\d{3}[\dX]$`, примеры Nature (печатный и электронный), The
  Guardian, Bioorganic & Medicinal Chemistry Letters (X), отрицательные
  примеры, ссылка на issn.org, перевод.
- `isbn10`, `isbn13`: отрицательные примеры с неверной контрольной цифрой,
  переводы.
- `ismn`: описание, `checksum: ismn`, примеры из Wikidata в обеих формах,
  ссылка на ismn-international.org, перевод.
- `isni`: описание, `checksum: iso7064_mod11_2`, категория `publishing`,
  примеры из Wikidata (Швейцария, ООН, Карл Мартелл с X), перевод.
- `orcid`: описание, regexp с блоком `0009-0000…0009-0010`,
  `checksum: iso7064_mod11_2`, категория `publishing`, отрицательные
  примеры, ссылка на описание формата ORCID, перевод.
- `doi`: описание, `parent: handle_id`, категория `publishing`, пример
  Elsevier с PII в суффиксе, отрицательные примеры (URL, префикс),
  ссылка на DOI Handbook, новый перевод. `doiprefix`: описание, категория,
  отрицательный пример.
- `udkindex`: описание своими словами, категории `publishing`, `science`,
  `classification: categorical`, regexp со знаками связи (`: + / ::`),
  определителями места `(…)`, языка `=…`, времени `"…"` и специальными
  определителями (`-`, `.0`, `'`) — 418 из 467 значений Wikidata (не
  приняты буквенные расширения и одиночные определители), примеры из
  Wikidata, ссылка на UDC Summary, новый перевод.
- `coden`: regexp `^(?:[A-Z]{5}|\d{2}[A-Z]{3})[A-Z0-9]$` (2972 из 3000;
  остальное — пятисимвольные коды до 1976 года и ошибки), описание,
  примеры JASCDU и NUTRHU, ссылка на CASSI, перевод.
- `bibcode`: regexp по описанию формата в Wikipedia и ADS (406 из 407),
  примеры Physical Review Letters и Agronomy Journal, перевод.
- `isil`: до 16 символов, описание, примеры из Wikidata (Библиотека
  Конгресса, Швейцарская национальная библиотека, Амброзианская
  библиотека, OCLC-DLC), отрицательный пример, перевод.
- `ocn`: описание своими словами (без сноски), категория `publishing`,
  отрицательный пример — форма поля MARC 035, ссылка на WorldCat, перевод.
- Категория `publishing` добавлена к `lccn`, `viafid`, `gnd_id`,
  `openlibid`, `worldcat_entities_id`, `worldcat_identities_id`.
- `bnf_id`, `lcnaf_id`, `nlm_unique_id`, `ringgold_id`, `pmid`, `pmcid`,
  `scopus_source_id`, `arxiv_id`, `publisher_item_identifier`, `gnd_id`,
  `lccn`, `openlibid`, `handle_id`: отрицательные примеры, переводы,
  ссылки.

## Что не сделано и почему

- `ru_bbk` без regexp: индексы ББК смешивают цифры, кириллицу, типовые
  деления и авторский знак (`Т3(2Г)0-64(2)я43`, `72 Д63`), а таблицы РГБ
  в открытом виде не найдены (страница ББК на rsl.ru отдаёт 404).
- `ru_grnti`: в Wikidata нет свойства; формат проверен по описанию
  ГПНТБ (три уровня) и рубрикам grnti.ru. Двузначный раздел без подрубрик
  regexp не принимает.
- Не добавлены: SPIN-код РИНЦ (не найден проверяемый источник формата),
  ISTC (в Wikidata нет свойства, агентство не подтверждено), SICI, Thema,
  BNE (свойство P950 помечено как устаревшее), JSTOR, ISBN publisher prefix
  (P3035), формат издания по ГОСТ 5773-90 (`60x84/16`), авторский знак.
  Кандидаты следующего раунда.
- Записи остаются `draft`. Кандидаты в `stable` после проверки человеком:
  `issn_l`, `ismn`, `isil`, `coden`, `bnf_id`, `lcnaf_id`, `lccn`,
  `gnd_id`, `ddc`.

## Находки для metacrafter-rules

Проверено pyparsing 3 на закреплённом коммите `19823306`:

- `common/science.yaml`, правило ORCID по значению:
  `Literal("0000-000") + Word(nums, exact=4) + ...` ждёт четыре цифры
  сразу после `0000-000`, а там цифра и дефис. Правило не находит ни
  одного настоящего ORCID (`0000-0002-1825-0097`) и не знает блока
  `0009-`.
- `common/media.yaml`, правило ISSN по значению: не принимает форму с
  дефисом и X (`0960-894X`) и компактную форму из восьми цифр
  (`00280836`).
- `common/media.yaml`, правило ISBN по значению: `Word(nums, exact=10)`
  стоит первой альтернативой `MatchFirst` и забирает первые 10 цифр
  13-значного ISBN, поэтому компактный ISBN-13 (`9780521293662`) не
  распознаётся.
- Для новых записей правил нет. По значению хорошо распознаются
  `urn_nbn`, `bisac_subject_code`, `msc_code`, `de_zdb_id`,
  `cz_nkc_aut_id`, `ru_grnti`; числовые ID (eLIBRARY.RU, РНБ, Crossref,
  HathiTrust, JPNO) — только по имени поля (`elibrary_id`, `authorid`,
  `grnti`, `bbk`, `udk`).
